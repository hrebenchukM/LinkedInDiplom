# 🔵 ЧАСТИНА 1: ТИМУР (Слайди 1–10)

## Слайд 1. Звіт: Вступ: чому саме LinkedIn

Доброго дня, шановні члени комісії!

Ми представляємо дипломний проєкт **LinkedIn Clone** — спеціалізовану платформу для професійного нетворкінгу, пошуку роботи, рекрутингу та комунікації.

**Розробники frontend:** Ямчук Тимур та Андрій Ротарь.  
**Розробники backend:** Гребенчук Марія та Прохорова Валерія.

Платформа спроєктована як повноцінна екосистема, що поєднує професійний профіль, мережу контактів, генерацію контенту, вакансії та realtime-взаємодію. Обраний формат LinkedIn дозволив комплексно продемонструвати розробку клієнтської частини: від побудови інтерфейсів (UI), складної маршрутизації та менеджменту станів до глибокої API-інтеграції з сервером.

Це не просто сайт з вакансіями, а професійна екосистема для кандидата, роботодавця та спільнот. Усі **6 основних розділів** платформи об'єднані в межах одного **Single Page Application (SPA)**, що забезпечує наскрізний шлях користувача: від реєстрації до комунікації в чатах.

**Технологічний стек:** React 19, Vite 6, React Router 7, **AppContext** для централізованого стану сесії та **SignalR** для протоколів реального часу. Інтеграція з сервером реалізована через REST API та двокомпонентну авторизацію **JWT** (access + refresh), а збереження даних відбувається в **PostgreSQL** через центральний шлюз **Facade.API**.

На захисті демонструємо **live-flow** через реальний API: вхід → профіль → стрічка → мережа → вакансії → чати.

## Слайд 2. Звіт: Файлова структура проєкту

На цьому слайді показано реальну структуру репозиторію. Фокус доповіді — **frontend SPA**, backend наведено для розуміння масштабу системи.

**Frontend** — наш основний шар розробки:
- **`src/app/`** — router, Layout, theme, i18n, AnimatedOutlet (переходи між сторінками);
- **`src/pages/`** — auth, home, network, vacancies, messages, notifications, admin;
- **`src/features/`** — бізнес-логіка модулів, API-виклики, mappers, enrich*-helpers;
- **`src/shared/`** — HTTP-клієnt, tokens, refresh, paths, спільні UI-компоненти та helpers.

**Backend** (контекст масштабу) реалізовано як **модульний моноліт**: Identity, Profile, Professional, Network, Content, Messaging, Jobs, Events, Notifications та центральний **Facade.API** як BFF-шар.

**Папка `scripts/`** містить інструменти автоматизації: **`verify-e2e.mjs`** — 17 smoke-тестів інтеграції frontend ↔ backend; **`verify-signalr.mjs`** — перевірка стабільності realtime-чатів; **`patch-i18n-keys.mjs`** — синхронізація перекладів для 4 мов.

У **`vite.config.js`** налаштовано **Reverse Proxy** для перенаправлення API-запитів на backend під час розробки. Production-збірка формується через **`npm run build`** у оптимізований bundle для деплою.

Структура відображає принцип: **pages — що бачить користувач, features — як це працює, shared — що перевикористовується**.

## Слайд 4. Звіт: Переваги UX нашого сайту

На слайді — **8 ключових переваг**, сформованих з того, що реально працює в поточній версії сайту на гілці **merger**:

1. **Єдиний UX** — одна навігація для всіх сценаріїв: головна, мережа, вакансії, повідомлення, профіль.
2. **Dark/Light** — перемикання теми через CSS variables без перезавантаження.
3. **i18n** — 4 мови інтерфейсу в runtime (uk, en, de, es).
4. **Картки** — зрозуміла структура контенту: пости, вакансії, контакти, повідомлення.
5. **Анімації** — **AnimatedOutlet**: плавні fade-переходи між сторінками без «стрибків» UI.
6. **Пошук** — **HeaderSearch** по профілях і контенту прямо з шапки.
7. **Live API** — JWT, REST, auto refresh токена, **SignalR** для messaging.
8. **E2E verify** — **17 автоматичних smoke-тестів** інтеграції frontend ↔ backend.

**Підсумок:** єдиний UX з темною/світлою темою, 4 мовами, плавними переходами та **live backend API** — не статичний макет, а працездатний інтерфейс.

## Слайд 5. Звіт: Що є у конкурентів і що додано у нас

**У конкурентів** типова проблема — розділення сервісів:
- вакансії живуть окремо від соціальної активності кандидата;
- пошук роботи не пов'язаний з чатами та мережею контактів;
- дипломні проєкти часто залишаються **статичними макетами** без backend;
- інтерфейс не показує повний шлях від входу до дії.

**У нашому LinkedIn Clone:**
- користувач **шукає роботу, веде профіль, читає контент і спілкується в одному місці**;
- вакансії, контакти та повідомлення об'єднані в **логічний кандидатський сценарій**;
- frontend **підключений до Facade.API**: auth, profile, feed, network, jobs, messaging;
- на захисті показуємо **live-flow**: login → profile → feed → network → vacancies → messages.

Цей слайд фіксує головну відмінність: ми не демонструємо «майбутню інтеграцію», а **працюючу систему** з реальними endpoint-ами.

## Слайд 6. Звіт: Компонентна структура frontend

Frontend побудовано як **набір ізольованих React-модулів** з чітким розділенням відповідальності:

- **`pages/`** — екрани за сценаріями: auth, home, network, vacancies, messages, notifications, admin;
- **`features/`** — API-виклики, mappers, **enrich***-helpers для профілів, постів, чатів;
- **`app/`** — router, **AppContext**, Layout, theme, i18n, page transitions;
- **`shared/api/`** — http, tokens, **refresh при 401**, централізовані paths;
- **`AppContext`** — auth, account, profile в **одному провайдері** замість legacy stores (AuthContext, ProfileStore, ChatStore тощо).

Архітектурний принцип: модулі **не залежать один від одного напряму** — спілкуються через shared API-шар і AppContext. Це спрощує підтримку, тестування та розподіл роботи в команді.

## Слайд 7. Звіт: Архітектура frontend

Архітектура frontend — **5 послідовних шарів**:

1. **React/Vite SPA** — UI, routing, компоненти, theme, i18n;
2. **AppContext** — auth, account, profile, **token refresh**;
3. **API client** — REST + JWT + **auto refresh при 401**;
4. **Facade.API** — BFF: auth, profile, content, network, jobs, messaging;
5. **SignalR + E2E** — realtime чати, **verify:e2e 17/17**.

**Результат:** frontend і backend працюють як **одна система**. SPA викликає REST API, SignalR обслуговує messaging, PostgreSQL зберігає дані на сервері.

## Слайд 8. Звіт: Маршрутизація frontend

Маршрутизація побудована на **React Router 7** з захистом приватних зон:

- **`/auth`** — login, register, **Google/Facebook OAuth**;
- **`ProtectedRoute`** — захист усіх маршрутів **`/app/*`**;
- **`AppContext`** — account, profile, **token refresh** при завантаженні додатку;
- **`/app/*`** — home, network, vacancies, messages, profile, notifications, admin;
- **`AnimatedOutlet`** — плавні **fade-переходи** між сторінками;
- **`redirect / → /app`** — стартовий сценарій після входу.

Публічні маршрути (splash, landing, auth) відокремлені від приватного контуру **`/app`**. Admin-маршрути додатково перевіряють роль **Admin** у JWT.

## Слайд 12. Звіт: Ямчук Тимур — вікно реєстрації

**Auth** — перша точка входу користувача в платформу. Без надійної авторизації жоден інший модуль не має сенсу.

Реалізовано **login/register** через **`/api/auth/*`** з двокомпонентною схемою **JWT**: короткоживучий **access token** для API-запитів і **refresh token** для безперервної сесії без повторного входу.

На екрані auth доступні кнопки **Google і Facebook OAuth** — для демонстрації соціального входу. Для захисту використовуємо перевірений demo-акаунт: **andrii.rotar@gmail.com**.

Після успішного входу **AppContext** зберігає **account** і **profile**, ініціалізує **auto refresh** токена при наближенні expiry. Користувач одразу потрапляє в **`/app`** без ручного перезавантаження сторінки.

Auth-екран стилістично узгоджений з усім сайтом: підтримка **dark/light theme** та **i18n** (4 мови). Валідація полів і повідомлення про помилки роблять сценарій **інтерактивним**, а не статичним макетом.

## Слайд 14. Звіт: Ямчук Тимур — пошук роботи

Пошук роботи перетворює модуль вакансій з «каталогу» на **щоденний інструмент кандидата**.

Реалізовано **фільтрацію** за ключовими словами, локацією, типом зайнятості, рівнем досвіду та remote-форматом. Користувач швидко переходить від загального списку до **релевантних** пропозицій.

Опрацьовано UX-сценарій **«немає результатів»**: інтерфейс не «ламається», а пропонує змінити параметри пошку — це важливо для реального використання, а не лише для demo.

Пошук тісно пов'язаний з **профілем** (навички впливають на AI-рекомендації) і **комunicацією** (після відгуку можна написати рекрутеру в чаті). Саме ця **синергія модулів** — головна перевага нашого рішення над класичними job-board.

## Слайд 18. Звіт: Андрій Ротарь — контентна стрічка (Feed)

**Feed** — **найскладніший архітектурний модуль** frontend-частини. Тут поєднуються глобальний стан, оптимізація рендерингу та динамічні реакції користувачів.

**Технічна реалізація:**
- пости завантажуються з **content API**;
- **enrichPostsWithAuthors** доповнює пости іменами та аватарами авторів;
- **AppContext + локальний state** — оновлення без full page reload;
- **PostCard**, reactions, comments оновлюються **точково** після дії користувача.

**Engagement flow:**
- **PostEngagement** — лайки та реакції;
- **PostCommentsPanel** — коментарі з live-оновленням;
- **PostShareMenu** — share постів у чат або мережу;
- **CreatePost modal** — rich text, media, hashtags;
- **PostViewRecorder** — фіксація переглядів.

Feed **технічно складніший**, ніж статичні форми auth або profile, бо тут постійно змінюється state при взаємодії багатьох користувачів. Саме тому цей модуль — **ядро архітектурної роботи** з моєї сторони.

*[Демо: /app → like → comment → create post]*

## Слайд 19. Звіт: Андрій Ротарь — архітектура Network

**Network** — модуль професійного нетворкінгу: контакти, запити, suggestions, groups, pages, events.

**Вкладка «Нові контакти»:**
- incoming/outgoing **connection requests**;
- **people you may know** — suggestions з API;
- **AddContactSearch** — пошук і додавання контактів;
- **ManageNetworkModal** — керування мережею.

**Вкладка «Активність»:**
- **EventPanel** з фільтрами All / Upcoming / Online / In-person;
- discover events з API;
- dark theme для панелі активності.

**Додатково:**
- **networkPageCache** — плавний UX без «блимання» skeleton;
- routes: **`/app/groups/:id`**, **`/app/event/:id`**, **`/app/company/:id`**.

Network показує, що наш продукт — **не job-board**, а **професійна соцмережа** з довгостроковою взаємодією.

## Слайд 20. Звіт: Андрій Ротарь — API-клієnt і backend-інтеграція

Frontend **повністю підключений** до **Facade.API** — auth, profile, content, network, jobs, messaging, notifications.

**API-шар (`shared/api/`):**
- **`http.js`** — Bearer token у кожному запиті;
- **auto refresh при 401** — безперервна сесія;
- централізовані **paths** і **error handling**;
- **`tokens.js`** — зберігання access/refresh у localStorage.

**Автоматизація якості:**

**Enrich-helpers** — `enrichPostsWithAuthors`, `enrichMessagingProfiles`, `enrichNetworkProfiles` — доповнюють API-дані профільною інформацією для UI.

**Demo-стек (Docker Compose):**
- PostgreSQL 16;
- Facade.API — **localhost:5000**;
- Vite frontend — **localhost:5173**.

Це **відтворювана** система: будь-хто з комісії може підняти проєкт і перевірити endpoint-и через **Swagger**.

## Слайд 22. Звіт: Підсумок

**LinkedIn Clone** — **full-stack професійна екосистема**: frontend + backend + PostgreSQL, а не окремий job-board.

На захисті демонструємо **live-flow**: login → profile → feed → network → jobs → chat.

**Головний результат** — інтегрований продукт з **E2E verify 17/17**, зрозумілим UX, dark/light theme, 4 мовами та realtime messaging.

Платформа об'єднує **роботу, контент, мережу контактів і комунікацію** в одному SPA — саме те, чого не вистачає класичним job-board.
